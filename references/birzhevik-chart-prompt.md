# Промпт: настроить макет через MCP

Скопируйте весь блок в Codex. Он поручает агенту работать инструментами MCP, а не выдавать список ручных действий. Основное подключение набора принудительно read-only; если другого разрешённого подключения нет, сначала потребуется один раз согласовать отдельное подключение для редактирования графика. Его запуск сам по себе не доказывает совместимость с вашим TradingView.

```text
Настрой для меня отдельный макет TradingView «Биржевик — реконструкция» через MCP. Не ограничивайся инструкцией, что мне нажать: сам вызови доступные инструменты, выполни поддерживаемые изменения и проверь результат чтением.

Используй https://github.com/evgyur/chip-hedge-fund-masterclass . Прочитай SKILL.md, references/tradingview.md, references/birzhevik-chart.md, assets/birzhevik-chart-settings.json, а также vendor/tradingview-chip/skills/tradingview-chip/SKILL.md и его references/permission-manifest.md. Если установленная копия старая, прочитай актуальные публичные файлы; локальные изменения не стирай.

Я разрешаю создать один новый отдельный макет для этой задачи и настроить в нём график, индикаторы, панели и шаблон индикаторов. Исходный макет и существующие шаблоны не заменяй. Не создавай сделки, торговые права, алерты, webhooks, подписки, расписания и новые платные услуги. Пароли, cookies и токены не извлекай и не проси в чате.

1. Проверь доступные MCP и схемы через tools_catalog, затем browser_list_tabs, layout_get и chart_get_state. Выбери фактически открытый Superchart и запиши target_id и native layout_id. Если нужных вкладок несколько и выбор неоднозначен, уточни только это.

2. Проверь, доступны ли layout_copy или layout_create, indicator_add, indicator_get_inputs, indicator_set_inputs и layout_save. В scripts/tradingview.mjs общего набора TV_READONLY принудительно включён: переменная TV_READONLY=0 не изменит поведение этого wrapper. Не пытайся обойти его отказ повторными вызовами.
Если уже есть разрешённое подключение TradingView Chip для изменения графика, используй его. Иначе один раз покажи и запроси подтверждение добавления отдельного stdio MCP «tradingview-chart-setup», не меняя основной read-only MCP: фактический Node.js 24+, абсолютный путь к vendor/tradingview-chip/src/server.mjs, TV_READONLY=0, TV_ENABLE_GENERIC_UI=0, проверенный loopback TV_CDP_ENDPOINT и отдельный приватный TV_DATA_DIR вне репозитория. Сохрани остальные подключения; синтаксис проверь по документации/справке установленного Codex, не выдумывай конфигурацию. Не запускай HTTP-сервер и не открывай отладочный порт наружу. Объясни, что этот отдельный сервер разрешает изменения и не является технически ограниченным только этой задачей: область применения ограничена моим разрешением выше. Если нужен перезапуск MCP или новый диалог, сохрани план и продолжи после него. Если подключение нельзя добавить, назови точный блокер, а не объявляй ручную памятку автоматической установкой.

3. Перед записью проверь незавершённые изменения исходного макета и Pine-буфер. При конфликте остановись, не сохраняй чужую работу автоматически. Предпочти layout_copy с именем «Биржевик — реконструкция» и одним сохранённым idempotency_key. Дальше работай только с возвращёнными target_id и новым expected_layout_id. Если макет с этим именем уже есть, не создавай второй и не перезаписывай его: сверяй журнал текущего задания либо уточни выбор. При таймауте сначала найди результат по прежнему ключу/ID, не повторяй создание вслепую.

4. В новом макете установи MOEX:SBER, 1D, обычные свечи. Сверь результат. Добавь встроенные EMA с периодами 9, 50, 100, 200 и источником Close; Bollinger Bands 20, SMA, Close, отклонение 2; CCI 20 HLC3, RSI 14 Close, MFI 14. EMA и Bollinger размести поверх цены, каждый осциллятор — на отдельной нижней панели. Для indicator_add используй поддерживаемые имена и force_overlay по схеме. После создания каждой сущности прочитай её input IDs через indicator_get_inputs, сопоставь имена/типы и только затем задавай значения; не угадывай in_0 и другие ID. Повторно прочитай значения. Не добавляй дубликаты уже подходящих индикаторов. Избыточные индикаторы в новой копии удаляй только по проверенным entity_id этой копии, не по названию и не из исходника. Если есть лимит тарифа или неподдерживаемая операция, останови затронутый шаг и укажи ограничение; ничего не покупай.

5. Оформление: белый фон, растущие свечи зелёные, падающие красные; EMA 9 чёрная, 50 оранжевая, 100 зелёная, 200 красная. Это приблизительная палитра, не подтверждённые RGB автора. Используй только реально доступные доменные MCP-команды. Если прямой настройки стилей нет, проверь study_template_snapshot и study_template_apply: изменять можно только прочитанные поля реально полученного шаблона новой копии, после локального резервирования и проверки схемы. Не синтезируй произвольную структуру native-шаблона. Повторно прочитай стили и группировку панелей. Сглаживание осцилляторов и смещение исходника не установлены: текущие значения сохрани и отметь как неподтверждённые. Не устанавливай LuxAlgo Nadaraya-Watson Envelope и не придумывай правила входа. Если MCP не умеет фон, цвета или нужное размещение, явно пометь эти поля как невыполненные; не подменяй их рисунком, случайным JavaScript, generic UI или вымышленным успехом.

6. Сохрани новый макет через layout_save и, если доступно, отдельный новый шаблон через study_template_save. Не заменяй существующий шаблон. После сохранения независимо прочитай saved layout ID, тикер, интервал, study IDs, параметры, панели и доступные стили; проверь сохранённый шаблон через study_template_get. Сохранение макета и шаблона — разные результаты. Сделай локальный скриншот, если MCP позволяет, не публикуя данные аккаунта.

7. Сохрани chart-setup.md в моей папке проекта: ID/ссылка нового макета, проверенные параметры, неподтверждённые значения, невыполненные шаги и точные причины. Не записывай секреты. Покажи ссылку на макет. «Готово» говори только для полей с readback; отдельно перечисли частичный результат. Не продолжай настройку других графиков. Если запускал отдельный браузер, сохрани макет и закрой только свои временные ресурсы либо явно оставь созданную вкладку для моего просмотра; чужие вкладки не трогай.
```

## Что автоматизировано, а что зависит от окружения

Включённый исходник MCP реализует создание/копирование макета, установку типа графика, добавление индикаторов, изменение их входов, снимки/применение/сохранение study-шаблонов и сохранение макета. Это подтверждено чтением исходного каталога, **не сквозным прогоном на аккаунте участника**. Прямых отдельных команд для фона и цветов EMA в закреплённом каталоге нет; изменение стилей через реально прочитанный native study-template требует проверки совместимости. Полная автоматическая расцветка не гарантируется. Промпт обязан отличить выполненные операции от отсутствующих возможностей.
